# 平面の壁取り合い（領域方式）

平面の壁仕上げ材（面線・妻線・内側線・木口線）と天板の輪郭は、**材の領域を合成してその境界を描く**
（`renderer/orthoRegion.js`＋`renderer/planWallRegion.js`）。線を後からトリムする旧方式（`wallJunctionResolve.js`
の6パス＋`finishLineSplits.js`）は 2026-09 に撤去した。**詳細LODも標準LODも同じ経路**（標準は内側線・木口線を
抑止するだけ。ユーザー確定2026-09）。

## なぜ領域か
線トリムは「取り合いの状況」を分類してから削る。分類は許容差と述語の組み合わせでパスごとに語彙が違い、状況
（高さ差・偏芯・柱包み・薄壁・駒）は組み合わせで増える——網羅し切れないことが不良（通り抜け・分割・多重書き）
の原因だった。壁は**すべて軸平行**なので、**直交矩形の合併境界**（1/1000mm 整数で厳密比較）で解けば、境界は
内部を通らず、共線の辺は1本に畳まれ、同じ辺は1回しか出ない。
- 層は2つ: `material`（下地∪仕上げ）と `backing`（下地）。`material` の合併境界＝面線と妻線、`backing` の
  合併境界のうち `material` の内部＝内側線と木口線。区別は線の向きだけで、トリムという処理は無い。
- 高さクラス（全高／腰壁の高さごと／垂れ壁）は別の領域として合成し、低いクラスは高いクラスを差し引く
  （高さの供給源は `finish/kneeDropWall.js` の `planWallHeight` のまま）。

## 消えるのは機構であって規則ではない（2026-09 設計レビュー）
「内側線どうしが取り合う」確定仕様は境界計算の帰結にはならない——壁生成の `closeConvexCorners` が出隅で端を
相手の材の遠位面まで伸ばすため、下地矩形をそのまま入れると角に仕上げ厚ぶんの断片が残る。規則は**矩形の
正規化**として残す（供給源は `finish/wallFinishJoin.js` の `finishJoinBoundary` 1箇所）:
- **下地の端は相手の内側線へ**（出隅＝短縮）。**入隅・正面からのT字は相手の下地の背面まで通す**——内側線で
  止めると2本の内側線に挟まれた下地の角の矩形が誰の材でもなくなり輪郭線が出る（1階 X=-1600×Y=-6000）。
  T字では相手の下地に隠れるので見た目は同じ。スタッドの範囲だけは内側線まで。材の端は入隅・T字で延長のみ。
  **薄壁も相手**（旧方式は薄壁の通し壁を無視した。実データでは薄壁の背後に必ずオーナー壁が在り図は同じ）。
- **旧パス6（通り抜けた端の詰め）は使わない**。通り抜けた材は合併で呑まれるだけで害が無く、詰めると十字で
  交差部の矩形が誰の材でもなくなる（1階 X=-3000×Y=-3500）。`endExtend` は外へ伸ばす分（パス0）だけ使う。
- **対称壁の材は下地の遠位面まで広げる**（下地は実在する材）。切ると軸CL内側の45mmが穴になり、反対側が
  薄壁のとき直交壁の材が薄壁の面線を覆えず素通りする（1階 x=6955×y=-3600）。広げた側の面は継ぎ目なので
  出さない。「外壁と内壁の `wallBase` が違う階の偽線」は 11.stq に無く、規則は持たない。
- 2a壁の描画クリップは壁id単位なので、クリップ単位が違う壁の線は畳まない（`clipGroups`）。
- 天板は (線種, 高さ) のクラスごとの領域。低いクラスは高い材（壁・柱壁）を差し引き（材の帯を厚み方向に覆う
  区間は描かず、高い材の面上の端部の線は出さない）、相互に相手の帯で終わる組は相手の帯の遠位面まで伸ばす
  ——外側どうしは遠位面・内側どうしは近位面で出会う（旧`capJoins`と同じ数値）。
- 柱壁は**覆い判定にだけ**参加する（材＝外形、下地＝外形を各辺の仕上げ厚で寄せたもの）。柱壁の線は
  `StructuralLayer.jsx` が `continued` で「壁の面線が引き継ぐ辺」を省いて描く——どちらが描くかは
  `finish/columnWrap.js` の `continued` 1箇所。包みの解決は `wallDrawPlan.js` の `planColumnWraps` を共有する。

## 残る「壁をまたぐ端の解決」（`wallJunctionResolve.js`）
- パス0（高さが違う壁）: `endExtend`（高い壁の端を低い壁の帯の遠位面まで）・`spanCuts`・`endWrap`。腰壁の帯は
  全高の領域に無いので帰結にならず、領域はこれを入力として使う。
- パス6（通り抜けた端の詰め）: 領域の矩形には使わない。効くのは `segments`＝略図の単線と間柱のピッチ原点だけ
  （実データで詳細・標準の線は1本も変わらない）。撤去の判断は別の観測を待つ。

## 変えない境界線
- ジオメトリ（`Wall.startOffset/endOffset` 等）は書き換えない。描画時だけの解決。
- 壁生成側のトリム（`closeConvexCorners`・`trimIntersectingWalls`・`trimStairUnderJunctions`）は残す。
- 出力は壁ごと（`wallLines`）。2a壁の描画クリップ・線種・key が壁単位のため。

## 計測（回帰の基準）
`app/scripts/probe/`（製品コードからは参照しない）。`11.stq` を Node へ復元し、描画セグメントを世界座標へ
落として比較する。`planDefects.mjs`: `through`（相手の材を完全に横切る。目標0）／`join`（端が相手の材の中で
終わる＝角の合流。参考値）／`split`（同種の線分どうし）／`overlap`。ゴールデン（`golden/`、詳細=`plan-*`・
標準=`plan-standard-*`）は**移行前の描画**で再生成しない。メトリクスを改訂したら `recountDefects.mjs` で
数え直して同じ物差しで比べる。移行前: 詳細 1階 2/25/19/2・2階 0/10/4/14、標準 1階 1/6/52/78・2階 0/0/21/36。
